AEGISWFP

See. Understand. Defend.

A Windows firewall and network intelligence app with two sides. Security Center lists every program talking to the network with a 0 to 100 risk score and the reasons behind it, flags duplicate, conflicting and too broad firewall rules, and shows which programs are listening for incoming connections and whether the firewall really lets them be reached. Family Shield is the simple side for parents: a PIN protected filter that blocks sites and games on the PC and on every phone on the home Wi-Fi, with ready-made bedtime and homework schedules.

Only one process can change anything. The WPF app runs as the user and can only ask. A Windows Service running as LocalSystem re-checks every request, the parent PIN and every domain before it acts. Every firewall change follows one path: preview, confirm, apply, change log, rollback.

The rule it is built on is the same one behind all my Aegis tools: show what is real, never just what a switch says. The blocked list is read back from the hosts file. “Protecting 3 devices” only appears after 3 devices really used the filter. A category with no trustworthy list says “not blocking yet”.

  • ▹ About 25,000 lines of C# including tests, across 12 projects with enforced boundaries
  • ▹ 559 tests passing in the release check (v1.8), and 16 bugs and weak spots found and fixed before release
  • ▹ Honest limits: the phone companion uses plain HTTP on the home Wi-Fi (HTTPS is next), and the installer is not code signed yet, so Windows still shows a warning
Technical details: architecture, security design, Family Shield
  • ▹ The App and Service talk over a named pipe. The Service writes to Windows Firewall, the hosts file, a DNS filter on port 53 and an admin-only SQLite database
  • ▹ Parent PIN stored as a salted PBKDF2 hash (210,000 iterations), with a lockout that grows up to 15 minutes
  • ▹ The built-in terminal has 15 fixed commands, typed arguments and no shell behind it, so command injection has nowhere to go
  • ▹ Hosts file changes stay inside AEGISWFP’s own markers, checked against a strict domain allow-list in the Service and again before writing
  • ▹ The DNS filter answers home network devices only and is rate limited per device, so it can never become an open resolver
  • ▹ The phone companion uses a one-time QR code that is swapped for a new key on first scan, and every tap is signed with HMAC-SHA256, a time stamp and a one-use random value
  • ▹ An optional AI analyst can explain findings in plain words. It is off by default, uses your own API key, and its code cannot reach the firewall or the Service
  • ▹ Family Shield safety rules: it never cuts anyone off, never pauses the parent’s PC, and never damages the hosts file

Aegis DiskGuard

Scan. Repair. Protect.

An SSD and HDD maintenance toolkit for Windows, built after a 128 GB laptop drive filled up and a clone tool sat at 0% with a 14 hour estimate. It puts backup, clone, repair, recovery and erase in one dark, simple app, in plain words, with a warning before anything destructive.

It runs as one .exe with nothing to install, built with the compiler already inside Windows. Every destructive step follows one path: check the disk is safe to touch, ask the person to type its disk number, run, then report in plain words.

  • ▹ About 6.1k lines of C# in nine source files, 13 pages: the dashboard and twelve tools
  • ▹ Real test: cloned a 128 GB NVMe to a 256 GB SSD at about 121 MB/s, booted from the clone and every app worked
  • ▹ Honest limits: most tools that change a disk still need more real drive tests, and Secure Erase is an overwrite, not the maker’s hardware erase
Technical details: toolkit, safety rules, honest limits
  • ▹ The toolkit: Backup and Restore, Clone, Check Drive, Repair Bad Sectors, Flash Drive Repair, File Recovery, Reformat, Rebuild Boot, Secure Erase, Extend Space, Space Map and Duplicate Finder
  • ▹ Raw disk reads and writes in 4 MB blocks, each job on its own thread with cancel, progress and speed
  • ▹ Your Windows disk and the disk the app runs from are hidden from every destructive tool, and you type the disk number before anything is erased
  • ▹ Clones stay offline so Windows does not bring two disks with the same ID online. Backups and recovered files can never be saved onto the disk they came from
  • ▹ Flash Drive Repair writes test patterns across the whole size to catch fake capacity drives, and says so instead of formatting them
  • ▹ The app says what software can not fix, for example that marking bad sectors on an SSD does very little

Aegis Sentinel

A malware, phishing and cleanup tool for Windows.

Eight tools in one window: Malware Scan, URL Check, Message Check, Device Tune-Up, Quarantine, Startup Manager, Activity Log and live protection that checks new files as they arrive. It started as a Python project called Skull Sentinel and is now one C# program with no Python and no installer.

Malware Scan uses two checks on every file: a SHA-256 fingerprint compared with known bad files, and a test for disguised programs like invoice.pdf.exe. Nothing is ever deleted on its own, and flagged files go to Quarantine where they can be restored any time.

  • ▹ URL Check scores a link before you click it, and Message Check shows why a text or email looks like a scam
  • ▹ Tested on my PC: live protection flagged a fake invoice.pdf.exe with a popup, and the tray icon turns on and off with the switch
  • ▹ Honest limits: a learning project, not a replacement for Windows Defender, with only a tiny list of known bad files
Technical details: live protection, structure, limits
  • ▹ Live protection in five steps: a new file lands, it waits until the copy is finished, it is checked, an alert pops up from the tray icon, and you decide to quarantine it or leave it alone
  • ▹ URL Check looks for fake brand names, look-alike spelling, risky endings, raw IP addresses, link shorteners and words like login and verify in odd places
  • ▹ Message Check looks for pressure words, deadlines and requests for passwords or OTP codes, and scores every link inside
  • ▹ Device Tune-Up is a CCleaner style cleaner: analyze first, then Run Cleaner. History and cookies start unticked, and it warns when a browser is still open
  • ▹ Startup Manager uses the same switch as Task Manager, marks odd entries CHECK and logs every change
  • ▹ Built as one program in five code files, with a single build.bat that uses the compiler already in Windows
  • ▹ Live protection watches three folders while the app runs, and link and message checks are rules of thumb

Aegis Warden

One click fixes for network and Windows problems, with a log that tells the truth.

I kept fixing the same problems by hand: slow internet, a stuck print queue, a PC that drags. My first version was a PowerShell script with a console menu. Aegis Warden is the same fixes as one .exe with a dashboard, a live log and 32 fixes in clear groups: Networking, Diagnostics, Disk and system, Printing and Tools.

The log never claims success it did not check. Every run ends as FINISHED, PROBLEMS or STOPPED, and a line with FAILED, ERROR, WARNING or Could not marks the run as PROBLEMS. Each fix asks once before it runs, and Cancel stops the whole process tree.

  • ▹ 24 plain language Knowledge Base articles explain each problem, with a search box that finds fixes and articles together
  • ▹ Version 1.1 added Network Reset, Wi-Fi Report, Slow PC Check, Ping and Trace and Save Report
  • ▹ Honest limits: the fixes were built and viewed on screen but not yet run on real Windows PCs, and some need administrator rights
Technical details: runner, log, safety
  • ▹ The original PowerShell fix bodies are kept as they were, so results match the old toolkit
  • ▹ Each fix goes to a temp script and runs in a hidden PowerShell on a background thread, so the window never freezes
  • ▹ Output streams in with time stamps and is also saved to a session file in Documents
  • ▹ Ping, trace and DNS lookup check the host name first, so odd characters never reach the command line. They are read only, so they run without a confirm box
  • ▹ One fix at a time, and the window will not close while one is running

AccPH

Real books for a Philippine business, not a toy ledger.

A Philippine payroll and accounting system, built phase by phase: authentication and six-role RBAC (enforced server-side, not just hidden buttons), employee and attendance management, and a deterministic payroll engine that computes SSS, PhilHealth, Pag-IBIG and BIR withholding tax from versioned government rate tables, never from a model's guess.

Approving payroll auto-posts a real double-entry journal entry into a general ledger. Recording a bill or invoice does the same for Accounts Payable and Receivable, and paying one posts a second, separate entry for the cash movement. The Trial Balance is computed live from posted entries only, so “Balanced? Yes” actually has to be earned.

Technical details: payroll engine, ledger design, engineering decisions
payroll calculation engine · a bug caught in live testing
// A Daily-rate employee's ₱700/day was fed straight into
// SSS / PhilHealth / Pag-IBIG - all three are legally MONTHLY schemes.
// A ₱700 "month" was qualifying for near-zero contributions.
//
// Fixed: convert to a monthly-equivalent salary first (rate × periods/month),
// look up the correct bracket, then divide the contribution back down
// to a per-period share. Monthly employees are unaffected (divisor = 1).
  • ▹ Deterministic calculation engine: every peso comes from a versioned rate table in the database, never computed by a model
  • ▹ "View Calculation" on every payroll line: names the exact rate-table row and effective date that produced each number
  • ▹ Real government rates: PhilHealth, Pag-IBIG and BIR withholding cited from primary sources; SSS cross-checked against a cited circular, one transcription error caught and corrected before it shipped
  • ▹ Draft → Approve and Draft → Post workflows. The one irreversible step is explicit and logged, everywhere
  • ▹ Free-tier AI honestly labeled as such: OCR receipt scanning with per-field confidence levels, and a rule-based Copilot that says "I don't know" rather than guessing

VisiQ

One visit ID, from registration to pharmacy.

A visit and queue management system for Philippine hospitals and clinics. A patient has one record, and every hospital trip gets one Visit ID. That same visit follows them through registration, doctor, laboratory, X-ray, cashier and pharmacy, each with its own queue number like D-025 or LAB-014, so the patient never starts over at each window.

Staff use a role based app with seven roles, and the administrator can change what each role may do. A TV board shows queue numbers only, unless names are switched on. Patients follow their place on their own phone from a QR code, with no account, using a random token that expires.

Technical details: queue engine, security, testing
  • ▹ Queue numbers come from a counter in the database, so they are never reused, even when two receptionists press the button together
  • ▹ Two staff pressing CALL NEXT at once get different patients, because the database locks the row. A double-click calls only one patient
  • ▹ A payment sent twice is saved once, because every payment form carries a one-time key
  • ▹ Supabase Auth handles passwords. Row-level security is on for every table with no open rules, and the server checks the user’s role on every request
  • ▹ Nothing important is deleted. Departments, services and users are hidden, and an audit log records who did what, when, and from which device
  • ▹ The WebSocket only says “something changed”. Patient data is never sent over it
  • ▹ 25 automated checks play the full 24 step patient journey over the real HTTP API, then test wrong passwords, missing CSRF tokens, role limits, bad QR tokens and the audit trail
  • ▹ Honest limit: the tests run on PGlite with one connection, so true parallel locking still needs a real check with two browsers on Supabase before go-live
